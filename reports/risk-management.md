# Project Risk Management & Mitigation Strategies

Below is the risk assessment matrix for the University Library Management System project, detailing potential risks, their likelihood, impact, and proposed mitigation steps.

| Risk Description | Likelihood | Impact | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| **Scope Creep:** Unmanaged or unexpected feature additions requested mid-project. | Medium | High | Freeze the system requirements early and stick strictly to the defined project scope. |
| **Team Member Inavailability:** Unexpected delays, illness, or absence of a teammate. | Medium | Medium | Cross-train team members so tasks can be shared or reassigned smoothly. |
| **Version Control Conflicts:** Git merge conflicts occurring during collaborative work. | High | Medium | Use separate feature branches (`git checkout -b feature-name`) and pull requests before merging code. |
| **Data Loss / Accidental Deletion:** Losing documentation, diagrams, or markdown files. | Low | High | Commit and push all local work to GitHub regularly at the end of each work session. |
| **Technical Bottlenecks:** Difficulty in designing specific diagrams or wireframes. | Low | Medium | Consult open-source templates, software engineering textbooks, or collaborate during team study sessions. |
